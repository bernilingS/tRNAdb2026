Referee: 1

Comments for the Author

The manuscript introduces an updated version of tRNAdb, which is a valuable
resource, and it is great to see the database being updated and
maintained. The manuscript is clearly written and easy to follow. It can be
recommended for publication after the following minor points are addressed.

Reply: We thank the reviewer for the kind verdict.

Minor comments

1. It would be useful to provide more cross-links from tRNAdb to external
resources. For example,
https://tdb.bioinf.uni-leipzig.de/results/trna/12100 states that the
sequence is from GtRNAdb 2.0, but there is no link to the corresponding
GtRNAdb entry. More generally, individual pages could link to the relevant
source databases wherever possible. For example,
https://tdb.bioinf.uni-leipzig.de/results/trna/240000 could link to NCBI
Taxonomy and to the GenBank record NC_000866.4. This would make it much
easier to navigate between tRNAdb and the underlying data sources.

REPLY: This is a great comment. We started implementing a comprehensive
       crosslinking framework for this already, and included links to the
       genome databases, RNACentral, gtRNAdb, PDB, MODOMICS, etc. where it
       was possible and feasible without extensive manual curation. As
       gtRNAdb is currently undergoing major updates and maintenance, we
       will introduce more comprehensive crosslinking to its resources as
       soon as it is fully available again.

2. I encountered an issue when using the taxonomy tree. I expanded the tree
to reveal cellular organisms and viruses and clicked the search icon next
to viruses, expecting to retrieve all viral sequences. Instead, the search
returned “Your query did not return any results.” This appears to happen
because the “Release” dropdown retains the value selected during a previous
search. When starting a new search from the taxonomy tree, this setting
should probably reset to “All releases”.

REPLY: This is a very valid remark. We implemented that change as the
       reviewer suggested. When a user follows the links provided in the
       taxonomy tree, all previously entered search fields are cleared and
       all relevant matches from the selected taxonomic group are
       retrieved.


3. The database filter in the API appears to accept only exact lowercase
values (trna, trna_rna and mttrna). Other spellings or capitalisations are
silently ignored, causing the API to return all data sources rather than an
error. For example, trna_rna returns 750 records, whereas tRNA_RNA returns
the entire database. This is particularly confusing because tRNA_RNA is the
form used in the API’s own responses. The same issue affects exports and
can therefore result in users unknowingly retrieving incorrect datasets.

REPLY: We thank the reviewer for catching this. We now cast every input to
       lower case, so these spelling variations are accepted now. We at the
       moment still do not perform "fuzzy" searches, hence not taking minor
       typos into account, though.

4. What is the planned release frequency for tRNAdb? Some of the underlying
analyses already appear to be approximately two years old. For example, the
archaeal genomes were analysed as of October 2024. It would be useful to
explain how frequently new releases are expected. Could this process be
automated, or does a new release require substantial manual review?

REPLY: We did the analysis after downloading the data, so the analysis is
       mainly about one year old. While largely automatized, many steps
       need human review in special cases (which are not infrequent). We
       are continously adding data at the moment, and we plan to continue
       to do so, which is why we have implemented a GUI supported pipeline
       for import.  We do expect to have funding for this purpose for the
       forseeable future; however, technically this is subject to periodic
       renewal applications, so that we do not mention this perspective in
       the manuscript. We added this to the paragraph about updates: "To
       enable a sustainable, continuous update procedure, we implemented a
       graphical user interface supported pipeline for import,
       normalization, and duplicate detection for subsequent tRNAdb
       versions."

5. The Terms of Use for tRNAdb (https://tdb.bioinf.uni-leipzig.de/tou)
appear unusually restrictive for a biological sequence database. In
particular, they explicitly prohibit use of the database in commercial R&D
pipelines. This is difficult to understand given that much of the
underlying information consists of naturally occurring tRNA sequences
obtained from existing public resources.  For example, GtRNAdb sequences
are also available through RNAcentral under CC0 and can therefore be freely
reused, including commercially. It seems particularly problematic if
sequences already available under CC0 effectively become subject to
additional restrictions when accessed through tRNAdb. I would encourage the
authors to reconsider the non-commercial restriction or, at minimum,
justify its necessity. The licensing terms should also be discussed
explicitly in the Data Availability section.

REPLY: This is a very valid point and we appreciate that this was brought
       up.  Our intent was to keep the data we provide free and public, and
       have resources built on this data be available to the academic
       community.  We can see how this more restrictive licensing type can
       also impact members of the research community down the line. Still,
       T-Psi-C provides its data under a license similar to CC BY 4.0. In
       order to avoid a mixed license for individual records, we decided to
       change our license to CC BY 4.0.  Still, with the extended
       crosslinking, tRNAdb users should be able to also obtain the
       sequences from their original datasource if they need to obtain the
       data with less strict licensing terms.


6. The font in Figure 3 is too small to read comfortably. For example, I
was unable to read the text describing the quality filters for Archaea. The
figure should be revised so that all labels are legible at normal
publication size.

REPLY: We somewhat increased the font, but as the figure is relatively big,
       it cannot get any bigger without compromising the overall
       layout. However, the figure is provided with high DPI as a scalable
       .pdf or high resolution png that can be zoomed, and we hope that
       this helps in readability.
 
Referee: 2

Comments for the Author

It is a nice effort to extend the seminal Sprinzl database.  The authors
should comment on whether the technical difficulties in the previous years
that led to interruptions can now be excluded.

REPLY:	 We thank the referee for his kind words. The connection to the database
	 was interrupted because the host (Leipzig University) deemed it too
	 insecure to be open to the www. The legacy database was implemented
	 in 2009 in a framework that was outdated even then. While we cannot
	 guarantee that there won't be any security issues for our modern
	 implementation, at the moment the underlying packages are still
	 updated regularly, and we hope that it will last at least 15 more
	 years.

The authors should also comment on what distinguishes tRNAdb from other
tRNA databases.

REPLY: This is a little hard at the moment, since we are aware that 2 other
       tRNA databases (t-psi-C and gtRNAdb) will receive major updates
       shortly. At the moment, we have the most complete collection of
       mitochondrial tRNAs, as well as a well documented API, and a
       different, sequence centric way to present and provide our data.
       Additionally, we provide a search mask that allows user to filter
       all entries in tRNAdb easily for a variety of metadata (taxonomy,
       taxonomic group, references, ...) and export user-defined custom
       datasets. Furthermore, we are located in Europe, in contrast to
       gtRNAdb.

       In the introduction, we added:
       "Located in europe, tRNAdb 2026 contains the most complete collection
       of mtRNA sequences and structures to date."

The "modern" design appears intuitive to someone who designed it. This
reviewer finds to color scheme of the 4 bases is very busy and begs the
question if that is what the few among us with colorblindness can be using
on a regular basis.

REPLY: There may be a slight misunderstanding of what we meant when writing
       about "design". The user interface and overall color scheme of the
       database was intentionally not changed substantially. We strived to
       keep the look and feel of the database close to the legacy
       implementation, which users have been using for mor than 15 years.
       Modern design is referring to the back-end of the database.  Still,
       the reviewers remarks regarding the coloring scheme are valid and we
       included a "High Contrast" mode that can be turned on and off with a
       button located at the top of relevant pages. This high contrast mode
       renders nucleotide characters in black on white and disables the
       colored boxes for regions.

The usability of the modified sequences remains questionable since there is
the addition of additional letters yet the identity of the chemical
modification cannot be deduced. That needs to be amended since tRNAs are
the most modified RNAs in a cell, and the interest in the biology of these
modifications is increasing.

REPLY: While there are explanations for the single one letter codes, we 
       agree that it would be useful to have more information regarding the 
       modified nucleotides immeadiately. We have implemented a mouse-over 
       for the sequences which shows the name, nucleotide of origin, and 
       the pubchem structure of the compound described by the one letter code. 
       The mouse-over feature is also available for the structure image of modified 
       tRNA entries. Additionally, we linked the .pdf that explains every modified 
       nucleotide letter code more prominently on the results pages for modified tRNAs.

       We also added a paragraph in the website description section:
       "Modified bases are displayed using an expanded legacy one letter
       code.  We implemented a mouse-over for the sequences and the
       structure image which shows the name, unmodified nucleotide of
       origin, and the PubChem structure of the compound
       described by the one letter code."
       
In some of the Figures the font is too small to read. The question being do
Figures 1, 2 and 5 have to be part of the manuscript?

REPLY: We did try to increase the fonts where possible, and we provide
       fully scalable figures. We think that the figures add to the
       manuscript, as they showcase the look and feel of the main access to
       the database and give interesting insights on the data contained in
       it. However, we would leave the decision whether to keep the figures
       at the discretion of the editor.
